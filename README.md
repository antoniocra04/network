# Связь

Монитор домашнего интернета для Raspberry Pi. Постоянно проверяет связь по слоям и одной фразой объясняет, что сломано и где: дома, у провайдера, в Рунете, на границе или у отдельного сервиса.

Go + HTMX + SQLite, один контейнер. Страница грузится целиком с Pi, без внешних CDN, поэтому открывается и тогда, когда интернета нет.

## Что проверяется

| Слой | Как |
|---|---|
| Дом | ping роутера (адрес берётся из таблицы маршрутов) |
| Провайдер | ping первого узла за роутером (ищется трассировкой), системный DNS |
| Рунет | ping узлов Яндекса и HTTPS-проверка ya.ru, vk.com, mail.ru, Госуслуг, Ozon |
| Граница | загрузка 128 КБ с Cloudflare, Hetzner, OVH (ловит обрыв на ~16 КБ); подмена DNS-ответов по UDP/53; доступность DoH |
| Зарубеж | ping 1.1.1.1, 8.8.8.8, 9.9.9.9 и HTTPS-проверка Google, Cloudflare, Wikipedia, Microsoft, Apple |
| Сервисы | YouTube, Telegram, WhatsApp, Discord, Instagram, ChatGPT, Claude, GitHub, Docker Hub и другие |

Каждый сайт и сервис проверяется по шагам: DNS → TCP → TLS → HTTP → загрузка. По тому, где ломается, определяется причина:

- **подмена DNS**: системный DNS говорит «нет такого домена» или отдаёт заглушку, а зашифрованный DNS знает настоящий адрес;
- **нет соединения по IP**: TCP не устанавливается;
- **блокировка по SNI**: TLS рвётся с именем сайта, но проходит с другим именем на тот же адрес;
- **страница блокировки**: провайдер подставляет страницу-заглушку;
- **обрыв после 16 КБ**: соединение замирает, получив 10–40 КБ;
- **сервис закрыт для региона**: сам сервис отвечает, что не работает в вашей стране;
- **отвечает медленно**: первый ответ дольше 3 секунд.

Если ping куда-то не проходит, а сайты открываются, монитор считает, что ICMP фильтруется, и не называет это аварией.

### Привычные блокировки не тревожат

Монитор запоминает обычное состояние каждого сервиса. Если Telegram или ChatGPT не открывались с самого начала, это «как обычно»: строка серая, без инцидента, раздел «Сервисы» остаётся зелёным. Новостью считается только изменение:

- сервис, который открывался, перестал открываться — жёлтый статус, инцидент и вердикт «Перестал открываться …»;
- заблокированный сервис снова открылся — заметка «Снова открывается …» в вердикте.

Если новое состояние держится сутки, оно само становится обычным.

## Разделы

- **Обзор**: вердикт, маршрут по слоям, все проверки, проблемные сервисы, инциденты за сутки, лента за 24 часа.
- **Сервисы**: по каждому сервису причина и шаги последней проверки.
- **Качество**: задержка и потери за 6 часов, сутки, неделю. Шкала логарифмическая и одинаковая на всех графиках.
- **Журнал**: инциденты со снимком всех проверок на момент начала, календарь за 13 недель, запуски монитора.
- **Проверить сайт**: проверка любого адреса, шаги появляются по мере выполнения.

Пока Pi выключена, на графиках «нет данных», а не авария.

## Запуск на Raspberry Pi

Нужны Docker и compose-плагин (Raspberry Pi OS 64-bit).

```bash
git clone https://github.com/antoniocra04/network.git svyaz
cd svyaz
docker compose up -d --build
```

Панель откроется на `http://<адрес-pi>:8083`.

Контейнер работает в сети хоста (`network_mode: host`): так он видит настоящий роутер, маршрут провайдера и тот же DNS, что и остальные устройства дома. Из прав оставлен только `NET_RAW`, он нужен для ping.

### Важно

- **Pi должна быть подключена кабелем.** Через Wi-Fi в замеры попадут проблемы самого Wi-Fi.
- **Pi должна ходить в интернет напрямую.** Если на роутере появится VPN, исключите из него адрес Pi, иначе монитор будет проверять VPN, а не провайдера.
- **Поставьте батарейку для RTC** (разъём BAT на Pi 5). Без неё после отключения питания и без интернета часы Pi собьются, и история поедет. Панель предупредит, если часы явно неверны.

## Настройка

Все проверки описаны в [internal/config/default.yaml](internal/config/default.yaml). Чтобы изменить список, положите `config.yaml` в папку `data/` рядом с `docker-compose.yml`. Любой список (`anchors`, `sites`, `services`, `throttle`) из этого файла целиком заменяет список по умолчанию; интервалы можно переопределить по отдельности.

```yaml
intervals:
  services: 5m
services:
  - { id: telegram, name: "Telegram", group: "Связь", url: "https://web.telegram.org/" }
  - { id: youtube,  name: "YouTube",  group: "Видео", url: "https://www.youtube.com/" }
```

После изменения: `docker compose restart`.

## Данные

SQLite в `data/svyaz.db`. Сырые замеры хранятся 14 дней, состояние слоёв раз в 15 секунд хранится 400 дней (десятки мегабайт в год).

## Разработка

```bash
go run ./cmd/svyaz            # http://localhost:8083, данные в ./data
```

На macOS без root ping идёт через непривилегированный ICMP-сокет. Если на машине включён VPN, который режет ICMP, монитор так и скажет.

Сборка образа под Pi на другой машине:

```bash
docker buildx build --platform linux/arm64 -t svyaz:latest .
```

## Чего пока нет

- замера скорости канала (кроме загрузки 128 КБ с зарубежных хостингов);
- сверки с внешними картами сбоев (IODA, Cloudflare Radar) и с реестром блокировок;
- проверки протоколов VPN (WireGuard, OpenVPN): для этого нужен свой сервер снаружи.
